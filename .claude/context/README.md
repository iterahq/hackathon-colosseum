# `.claude/context/` — intencionalmente vazio

Este diretório carregava três arquivos herdados do scaffold gerenciado de
`devfellowship/dfl-iterate`. Todos foram **removidos em 2026-07-31**, e a
remoção é deliberada: não recrie nenhum deles sem ler o que segue.

Os três se anunciavam como *"Auto-generated by `/sync:push`. Do not edit
manually."* — **e essa afirmação era falsa**. Não existe `/sync:push` neste repo,
nada nunca os regenerou, e o `iterahq/itera-player` não aparece no
`registry/distribution-manifest.yaml` do `dfl-hq` (que só conhece
`devfellowship/dfl-iterate`, num pipeline `execution_mode: stage-only` com
`apply_writes_enabled: false`). Ou seja: eram conteúdo estático fingindo ser
conteúdo gerenciado — a pior combinação, porque o aviso "não edite" impedia a
correção enquanto o conteúdo apodrecia.

O que cada um dizia, e por que sair era melhor que corrigir:

- **`business.md`** e **`dependencies.md`** — nunca foram renderizados. O
  conteúdo literal em disco era o template Handlebars cru: `{{repo_name}}`,
  `{{#each personas}}`, `{{synced_at}}`. Zero informação.
- **`ecosystem.md`** — renderizado, mas para a **DFL**, não para a Itera. Dizia
  que a instância Supabase é a `yoojxnggaxcqtsyjdrdx` (**a prod da DFL** — o
  banco que este repo nunca deve tocar; o da Itera é o `kjefmwlopzeaqgqtlbdn`),
  que o client fica em `src/integrations/supabase/client.ts` (aqui é
  `src/lib/supabase/client.ts`), que DDL vai por PR no `dfl-schema` (aqui vai em
  `db/migrations/`) e que o bundler é Vite 5 (é Vite 8). Um agente que confiasse
  nele era mandado para o banco errado.

**A informação verdadeira e mantida está em:**

| O quê | Onde |
| --- | --- |
| Arquitetura, engine de activity, convenções | [`../../CLAUDE.md`](../../CLAUDE.md) |
| Regras para agentes, governança de schema | [`../../AGENTS.md`](../../AGENTS.md) |
| Contrato legível por máquina (stack, env, rotas) | [`../../repo-contract.yaml`](../../repo-contract.yaml) |
| Banco: schema, RLS, como aplicar migration | [`../../db/README.md`](../../db/README.md) |
| Metadados do repo para agentes | [`../manifest.yaml`](../manifest.yaml) |

Esses quatro primeiros são verificados na CI pelo job `docs-drift`
(`scripts/verify-docs.sh`). Doc que não está sob esse gate tende a apodrecer —
foi exatamente o que aconteceu aqui.
